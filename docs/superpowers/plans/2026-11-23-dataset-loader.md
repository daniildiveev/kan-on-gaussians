# План реализации загрузчика датасетов

> При реализации в текущем чате использовать `superpowers:executing-plans`; при выборе отдельных исполнителей — `superpowers:subagent-driven-development`. Отмечать выполненные шаги в чекбоксах. Коммиты и PR ведёт пользователь.

**Цель.** Подать локальный числовой CSV или UCI Concrete в обе активные модели через один вызов и стандартный PyTorch DataLoader.

**Архитектура.** Сначала прочитать и проверить исходную таблицу, затем выделить группы и получить индексы выборок. Общая функция подготовки работает только с массивами, группами и номером fold. Сетевой ввод нужен только именованному датасету при первом явном скачивании.

**Стек.** Python 3.11+, стандартные `csv`, `urllib.request` и `tempfile`, NumPy для совместимого с архивом генератора и статистик, PyTorch TensorDataset, pytest.

**Спецификация.** [Согласованный дизайн](../specs/2026-11-23-dataset-loader-design.md).

## Общие ограничения

Публичный путь импорта — `mgs_kan.data`. Дефолты — `root="data"`, `fold=0`, `download=False`. Пять folds, seed 13601. Статистики вычисляются в float64 с делителем N по train. Модели получают CPU float32. Архивные исходники остаются эталоном для проверки воспроизводимости. Тестовый набор работает офлайн.

## Что проверить особенно внимательно

- Повторяющийся заголовок и целевая колонка в середине таблицы — проверка схемы и порядка признаков в задаче 1.
- Константный столбец, константная цель и выброс только в test — проверка масштаба и обратного преобразования в задаче 1.
- Слишком мало групп или fold вне диапазона 0–4 — понятная ошибка до вычисления статистик в задаче 1.
- Один рецепт при нескольких возрастах — все его строки остаются в одной выборке в задаче 2.
- Частичный ответ сервера и повреждённый локальный файл — проверка повтора и сохранности оригинала в задаче 3.
